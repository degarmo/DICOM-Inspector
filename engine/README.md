# DICOM Inspector: comparison engine

A Python CLI that compares the headers of two DICOM files and prints the
differences as JSON. The desktop app runs this engine as a child process and
reads its stdout, so the JSON shape below is a versioned contract.

**This tool is read-only and never sends data anywhere.** It only opens files
for reading, never loads pixel data (`stop_before_pixels=True`), and makes no
network calls or telemetry requests.

## Install

Requires Python 3.11+.

```sh
cd engine
python3 -m venv .venv
source .venv/bin/activate
pip install -e '.[dev]'
```

## Usage

```sh
python -m dicom_inspector compare <file_a> <file_b> [--only-diffs] [--pretty] [--force]
```

| Flag           | Effect                                                                 |
| -------------- | ---------------------------------------------------------------------- |
| `--only-diffs` | Drop `identical` rows. `summary` still counts every row.               |
| `--pretty`     | Indent the JSON with 2 spaces. Default output is a single compact line. |
| `--force`      | Read files that lack the 128-byte preamble and `DICM` prefix.          |

Examples (fixtures are generated by `python tests/make_fixtures.py`, or by running `pytest`):

```sh
# Full report, one line of JSON
python -m dicom_inspector compare tests/fixtures/01_study_uid_a.dcm tests/fixtures/01_study_uid_b.dcm

# Only the differences, human-readable
python -m dicom_inspector compare tests/fixtures/06_nested_sequence_a.dcm \
    tests/fixtures/06_nested_sequence_b.dcm --only-diffs --pretty

# A bare dataset with no preamble needs --force
python -m dicom_inspector compare tests/fixtures/10_no_preamble_a.dcm \
    tests/fixtures/10_no_preamble_b.dcm --force
```

## Exit codes

| Code | Meaning                                                                         |
| ---- | ------------------------------------------------------------------------------- |
| 0    | Files were compared. Differences are reported in the JSON, not via exit code.  |
| 1    | Unexpected error, including invalid command-line usage.                         |
| 2    | A file is missing, unreadable, or not valid DICOM.                              |

On exit 1 or 2, stdout is empty and stderr carries one line of JSON:

```json
{"error": {"code": "not_dicom", "message": "File is missing the DICOM preamble and 'DICM' prefix. If it is a raw DICOM dataset, re-run with --force.", "file": "scan.dcm"}}
```

| `code`           | Exit | Meaning                                                        |
| ---------------- | ---- | -------------------------------------------------------------- |
| `file_not_found` | 2    | Path does not exist.                                           |
| `not_a_file`     | 2    | Path is a directory or other non-regular file.                 |
| `unreadable`     | 2    | The OS refused the read (permissions, I/O error).              |
| `not_dicom`      | 2    | No DICOM prefix (without `--force`), or unparseable even with it. |
| `invalid_dicom`  | 2    | The content could not be parsed, the file is truncated (cut off inside an element), or it has no data set. |
| `usage_error`    | 1    | Bad arguments. `file` is `null`.                               |
| `internal_error` | 1    | Bug in the engine. `file` is `null`.                           |

## Output schema (`schema_version` "1.0")

stdout is a single JSON object, ASCII-only (non-ASCII text is `\uXXXX`
escaped), followed by a newline. The same input always produces byte-identical
output.

```json
{
  "schema_version": "1.0",
  "files": {
    "a": {
      "path": "/abs/path/06_nested_sequence_a.dcm",
      "size_bytes": 740,
      "sha256": "9470876338f5a88156d5210997953772470b5ed1e27195b42e6fb12c48c14a05",
      "transfer_syntax": {"uid": "1.2.840.10008.1.2.1", "name": "Explicit VR Little Endian"},
      "sop_class": {"uid": "1.2.840.10008.5.1.4.1.1.7", "name": "Secondary Capture Image Storage"}
    },
    "b": { "...": "same shape as a" }
  },
  "summary": {
    "total": 32,
    "identical": 31,
    "different": 1,
    "only_in_a": 0,
    "only_in_b": 0,
    "priority_mismatches": 0
  },
  "warnings": [],
  "rows": [
    {
      "path": "(0008,1115)[0].(0008,114A)[0].(0008,1155)",
      "keyword_path": "ReferencedSeriesSequence[0].ReferencedInstanceSequence[0].ReferencedSOPInstanceUID",
      "tag": "(0008,1155)",
      "keyword": "ReferencedSOPInstanceUID",
      "vr": "UI",
      "value_a": "2.25.3001",
      "value_b": "2.25.3002",
      "status": "different",
      "is_private": false,
      "private_creator": null,
      "is_priority": false,
      "vr_a": "UI",
      "vr_b": "UI",
      "vr_mismatch": false
    }
  ]
}
```

### `files.a` / `files.b`

| Field             | Type                     | Notes                                                       |
| ----------------- | ------------------------ | ----------------------------------------------------------- |
| `path`            | string                   | Absolute path.                                              |
| `size_bytes`      | int                      | Size of the whole file on disk.                             |
| `sha256`          | string                   | Hex SHA-256 of the whole file.                              |
| `transfer_syntax` | `{uid, name}` or `null`  | From (0002,0010). `null` when the file has no file meta.    |
| `sop_class`       | `{uid, name}` or `null`  | SOPClassUID, falling back to MediaStorageSOPClassUID.       |

### `summary`

Counts are over **all** rows, even with `--only-diffs`. `priority_mismatches`
counts rows with `is_priority: true` and a status other than `identical`.

### `warnings`

Problems that did not stop the comparison:
`{"code", "message", "file": "a"|"b", "path": string|null}`.

| `code`                        | Meaning                                                                            |
| ----------------------------- | ---------------------------------------------------------------------------------- |
| `decode_error`                | Text could not be decoded with the file's Specific Character Set. The value is shown as a bytes summary and compared on raw bytes. |
| `unknown_character_set`       | Unsupported Specific Character Set term. Text is decoded with pydicom's default.  |
| `value_error`                 | An element value could not be interpreted. It is shown and compared as raw bytes. |
| `duplicate_file_meta_element` | A group 0002 element also appears in the main dataset. The file meta copy is used. |
| `reader_warning`              | A warning raised by the DICOM reader (pydicom), passed through verbatim.          |

### `rows`

One row per element path present in either file, covering file meta
(group 0002) and the main dataset. Sequences are flattened recursively.
Rows are sorted by tag path, comparing tags and item indexes numerically.

| Field             | Type                        | Notes                                                                                          |
| ----------------- | --------------------------- | ---------------------------------------------------------------------------------------------- |
| `path`            | string                      | Stable key, e.g. `(0008,1115)[0].(0020,000E)`.                                                 |
| `keyword_path`    | string                      | Readable path, e.g. `ReferencedSeriesSequence[0].SeriesInstanceUID`. Unknown and private tags appear as `(gggg,eeee)`. |
| `tag`             | string                      | `(gggg,eeee)`, upper-case hex.                                                                 |
| `keyword`         | string                      | DICOM keyword, or `""` if unknown or private.                                                  |
| `vr`              | string                      | VR from A, or from B when the element is only in B.                                            |
| `value_a`         | string, string[], or `null` | `null` when the element is absent from that file.                                              |
| `value_b`         | string, string[], or `null` | As above.                                                                                      |
| `status`          | string                      | `identical`, `different`, `only_in_a`, or `only_in_b`.                                         |
| `is_private`      | bool                        | Odd group number.                                                                              |
| `private_creator` | string or `null`            | Private creator of the element's block (for a creator element, its own value). `null` when not private. |
| `is_priority`     | bool                        | See below.                                                                                     |
| `vr_a` / `vr_b`   | string or `null`            | VR on each side; `null` when absent.                                                           |
| `vr_mismatch`     | bool                        | Both present with different VRs. Such rows are always `different`.                             |

Value rendering (deterministic, JSON-safe):

- Multi-valued elements become a list of strings.
- Person names become a string such as `"FAMILY^GIVEN"`.
- Binary VRs (OB, OW, OF, OD, OL, OV, UN) become `"<N bytes, sha256:xxxxxxxxxxxx>"` (first 12 hex digits). Raw bytes are never emitted.
- Sequences become `"<N items>"`, and their contents appear as separate rows.
- Strings longer than 256 characters are cut to 256 and end with `…(+N chars)`.
  Comparison always uses the full, untruncated value. Two rows can show the
  same text and still be `different`.
- Text is decoded with the Specific Character Set in effect, including
  per-item overrides inside sequences.

### Priority tags

`is_priority` is `true` for PatientID, IssuerOfPatientID, AccessionNumber,
StudyInstanceUID, SeriesInstanceUID, SOPInstanceUID, SOPClassUID, Modality,
StudyDate, StudyTime, SpecificCharacterSet, TransferSyntaxUID, and every
private tag. Matching is by tag, so priority tags nested in sequences count too.
The list lives in `dicom_inspector/priority.py`.

## Tests

```sh
pytest
```

`tests/make_fixtures.py` builds every fixture from scratch with pydicom, using
obviously fake values (for example `PatientName = "TEST^SYNTHETIC"`). No real
patient data is used anywhere. pytest regenerates the fixtures at the start of
every run into `tests/fixtures/`, which is git-ignored.

| Fixture pair         | Planted difference                                                  |
| -------------------- | ------------------------------------------------------------------- |
| `01_study_uid`       | StudyInstanceUID changed                                            |
| `02_blank_accession` | AccessionNumber blank in B                                          |
| `03_issuer`          | IssuerOfPatientID changed                                           |
| `04_charset`         | ISO_IR 100 vs ISO_IR 192 with the same non-ASCII name (only the charset differs) |
| `05_private_block`   | Private block with creator only in B                                |
| `06_nested_sequence` | Value changed two sequence levels deep                              |
| `07_transfer_syntax` | Explicit VR Little Endian vs Explicit VR Big Endian                 |
| `08_identical`       | None                                                                |
| `09_not_dicom`       | B is a text file (exit 2, with or without `--force`)                |
| `10_no_preamble`     | B has no preamble or file meta (needs `--force`)                    |
| `11_vr_mismatch`     | StudyDescription written as SH instead of LO                        |
| `12_long_value`      | 300-character comment differing after character 256                 |
| `13_decode_error`    | B declares UTF-8 but contains Latin-1 bytes                         |
| `14_implicit_vr`     | Explicit vs Implicit VR Little Endian                               |
